# v0.2.0-alpha.1 Alpha 发布说明

状态：已于 2026-09-05 发布 `v0.2.0-alpha.1` tag 与 GitHub Release。

我在这轮 Alpha 中把项目从可安装 CLI 和只读检查，推进到可以在本地仓库上运行的完整 Agent harness。当前包版本是 `0.2.0a1`，公开 tag 为 `v0.2.0-alpha.1`。

## 这次新增

1. **完整运行链路**：我接入了 CLI、Pico runtime、有界 Agent loop、prompt/context 管理、工具解析和停止条件。
2. **四类 Provider**：我保留 DeepSeek、OpenAI 兼容、Anthropic 兼容和 Ollama 的配置与 client 适配，真实调用仍由用户显式启用。
3. **工作区工具**：我提供 list、read、search、write、patch、shell 和受限 delegate。主 CLI/runtime 的文件工具会校验工作区路径，高风险工具经过 approval policy。
4. **会话与恢复**：我加入 session、task state、run store、trace、report、checkpoint、resume、working memory 和 durable memory。
5. **离线评测证据**：我加入固定 benchmark、fixture、FakeModelClient、上下文/记忆/恢复对照实验、复现脚本和脱敏结果。

## 安全与兼容性

- 我不会把真实凭据、`.env`、`.pico/`、缓存、虚拟环境或私有资料提交到仓库。
- 默认测试和 CI 不读取真实凭据，也不联网调用 Provider。
- 主运行时的 `run_shell` 使用过滤后的环境变量、超时和 approval policy，但仍通过 `shell=True` 启动宿主 shell；它不构成工作区或操作系统级沙箱。
- `pico.guarded_workspace` 的参数数组执行和高风险命令拦截尚未接入主 CLI/runtime，不属于主运行时默认生效的保护。
- Provider 配置、CLI 参数、本地存储格式和 Alpha API 仍可能在后续版本中调整。

## 已知限制

- benchmark 结果来自固定 fixture 和 FakeModelClient，只能说明当前 runtime 合同及模块行为，不能外推真实模型质量、成本、延迟或线上成功率。
- Ollama 需要本地服务和已准备好的模型；HTTP Provider 需要用户自行配置可用的 endpoint 与凭据。
- 本次发布保留已经公开的 `v0.1.0` tag 与 Release，不改写已发布历史。
